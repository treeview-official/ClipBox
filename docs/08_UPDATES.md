# 1.2 업데이트·패치노트·문의

[1.2.0 실제 화면 갤러리](SCREENSHOTS.md)에서 업데이트 확인·패치노트·문의 화면을 볼 수 있습니다.

## 1.0.0 또는 1.1.0에서 처음 올리기

기존 버전에는 업데이트 버튼이 없으므로 [1.2.0 설치 파일](https://github.com/treeview-official/ClipBox/releases/tag/v1.2.0)을 한 번 내려받아 설치합니다. 실행 중인 ClipBox를 완전히 종료한 뒤 같은 사용자 계정으로 설치하세요. Mac은 응용 프로그램 폴더의 기존 ClipBox를 새 앱으로 교체합니다. 앱의 데이터 폴더를 삭제하지 않으면 기존 기록·즐겨찾기·설정을 그대로 사용합니다.

## 다음 버전부터 앱 안에서 업데이트하기

1. **환경설정 → 프로그램 업데이트 → 업데이트 확인**을 누릅니다. 패치노트 화면에서도 확인할 수 있습니다.
2. 더 높은 정식 버전이 있으면 현재 버전과 공개 최신 버전을 표시합니다. 같은 버전이나 낮은 버전으로는 설치를 제안하지 않습니다.
3. **업데이트 다운로드**를 누릅니다. 진행률을 볼 수 있고 취소·재시도할 수 있습니다.
4. 다운로드가 완료되면 파일 크기와 SHA-256을 확인합니다. 저장하지 않은 환경설정이 있다면 먼저 저장합니다.
5. **앱 종료 후 설치 → 업데이트 설치**를 누릅니다. 설치 파일을 정상적으로 연 경우 ClipBox가 종료됩니다. 운영체제의 설치 화면에서 마무리하세요.

| 환경 | 선택되는 파일 | 마무리 |
|---|---|---|
| Windows x64 | EXE | 설치 마법사의 안내에 따라 설치 |
| Mac Apple Silicon / Intel | 실행 중인 앱 CPU에 맞는 DMG | ClipBox를 응용 프로그램 폴더로 옮겨 기존 앱 교체 |
| Ubuntu/Debian 계열 x64 | DEB | 소프트웨어 설치 앱에서 설치·필요 시 관리자 인증 |
| Fedora/RHEL 계열 x64 | RPM | 소프트웨어 설치 앱에서 설치·필요 시 관리자 인증 |
| 그 외 Linux x64 | TAR.GZ | 새 폴더에 풀고 새 앱 실행; 메뉴·자동 시작 경로 변경 필요 |

설치 프로그램이 연결되지 않았다면 **파일 위치 열기**로 다운로드한 파일을 확인한 뒤 해당 OS의 설치 앱으로 여세요. Linux에서 압축 프로그램이 열렸다면 파일을 우클릭해 소프트웨어 설치 앱을 선택하거나 [설치 가이드](INSTALL.md)의 apt/dnf 명령을 사용합니다.

현재 방식은 검증한 설치 파일을 열어 운영체제 설치 절차로 연결합니다. 백그라운드 자동 무인 교체나 자동 재시작은 제공하지 않습니다. Windows 인증서 서명과 Apple Developer ID 서명·공증은 미적용입니다. macOS의 자동 업데이트는 코드 서명이 필요하므로 현재는 DMG 교체 방식입니다. [electron-builder 공식 안내](https://www.electron.build/v26/docs/features/auto-update/)

## 패치노트와 문의

왼쪽 **환경설정 바로 아래 → 패치노트**에서 버전별 변경 사항을 봅니다. 설치된 앱까지의 패치노트는 로컬에 포함되어 인터넷 없이 표시합니다. 업데이트를 확인한 뒤에는 GitHub 최신 배포 안내도 펼쳐 볼 수 있습니다.

요청사항·오류 문의는 **tree_view@naver.com**으로 보내 주세요. 앱의 이메일을 클릭하면 기본 메일 앱의 작성 창을 엽니다. 메일을 자동 발송하거나 기록을 첨부하지 않습니다. OS·ClipBox 버전과 오류 상황을 알려 주시면 도움이 됩니다.

## 데이터와 네트워크

- 업데이트 확인·다운로드 버튼을 눌렀을 때만 main 프로세스가 공개 GitHub Releases에 연결합니다. 시작 시 자동 확인은 없습니다.
- 클립보드·설정 데이터는 업데이트 요청에 포함하지 않습니다. 일반 네트워크 요청처럼 GitHub/CDN이 IP와 HTTP 요청 정보를 받습니다.
- 렌더러의 외부 통신은 계속 차단합니다. 렌더러에서 URL이나 설치 경로를 전달할 수 없습니다.
- 정식 릴리스, 고정 저장소·파일명·CPU, HTTPS 리디렉션 대상, 최대 크기, GitHub SHA-256을 검사합니다. 설치를 열기 직전에도 해시를 다시 확인합니다. SHA-256은 파일 무결성 확인이며 개발자 인증서 서명을 대체하지 않습니다.
- 설치 파일은 OS 임시 폴더에 보관합니다. 취소·실패·다시 확인 시 앱이 만든 해당 파일만 정리하며 기록 DB와 설정은 건드리지 않습니다. 설치를 위해 연 파일은 설치 프로그램이 사용하므로 즉시 삭제하지 않습니다.

## 검증

[소스 CI](https://github.com/treeview-official/ClipBox/actions/runs/39910839190)에서 타입·소스 빌드와 Windows 단위 48개(2개 POSIX 전용 건너뜀), macOS·Ubuntu 각각 50개 검사가 통과했습니다. 업데이트 검사는 버전 비교, OS/CPU·배포판 선택, 출처와 해시 검증, 손상·변조 차단, 취소와 재시도, 설치 프로그램 연결 실패를 포함합니다. 각 OS 파일 형식의 다운로드·연결은 합성 응답과 대역 설치 실행기를 사용한 검사입니다.

[업데이트 UI 검사](../artifacts/qa/v1.2.0/update-ui-results.json)는 실제 Electron·preload IPC·React 화면을 임시 프로필에서 사용했습니다. 네트워크 응답만 합성하며 설치 파일 실행·메일 전송·클립보드 접근은 수행하지 않았습니다. 정렬, 패치노트, 문의 주소, 업데이트 안내·취소·재시도, 미저장 설정 보호, 동일·이전 버전 차단, 850×560 창을 확인했습니다.

네이티브 패키지 검증과 파일 해시는 [1.2.0 릴리스](https://github.com/treeview-official/ClipBox/releases/tag/v1.2.0)의 기록을 확인하세요. RPM의 Fedora/RHEL 설치·실행, Wayland, 실제 구버전에서 신버전까지의 대화형 설치 완료·자동 재시작, Windows 게시자 인증과 macOS Gatekeeper 전체 흐름은 별도 검수 대상입니다.
